## Детальний розбір коду — `part2_tipping.py`

Мета: на основі двох вхідних змінних — `food` і `service` — систему пропонує рекомендацію чайових (`tip`) у відсотках.

1) Імпорти й налаштування:
   - `numpy`, `skfuzzy` (`control` як `ctrl`), `matplotlib` та `os`.
   - Створюється папка `results_part2` для збереження графіків.

2) Оголошення змінних нечіткої логіки:
   - `food` та `service` — antecedents на дискретній сітці 0..10.
   - `tip` — consequent на дискретній сітці 0..25.

3) Функції належності:
   - Для `food` і `service` використано `automf(3)` — автоматично створюються 3 функції належності (poor, average, good). Це зручно для лабораторної: параметри обрані бібліотекою за замовчуванням.
   - Для `tip` задаються три трикутні функції: `low`, `medium`, `high` зі зрізом у центрі (див. код для точних крайових значень). Це визначає, як вивід розподіляється на категорії.

4) База правил (rules):
   - Якщо їжа або сервіс погані → `tip` = low.
   - Якщо сервіс середній → `tip` = medium.
   - Якщо сервіс або їжа хороші → `tip` = high.

5) Симуляція тестового прикладу:
   - Вхід: `food=6.5`, `service=9.8`.
   - Викликається `compute()` → вивід виводиться у відсотках.
   - Використовується дефазифікація, яку за замовчуванням у `skfuzzy` виконує метод центроїда (centroid) — це варто згадати при захисті.

6) Графіки:
   - `part2_tipping_result.png` — графік дефазифікації та урахування активних ступенів належності (позначається вертикальною лінією з остаточною рекомендацією).
   - `part2_food_mf.png`, `part2_service_mf.png` — графіки функцій належності для вхідних змінних.

Пояснення результату (як пояснити викладачу):
- Для наведених вхідних значень сервіс дуже високий → вага правил, що дають `high tip`, переважає. Водночас `food=6.5` — вже між середнім і хорошим, отже сумарний результат за дефазифікацією дає певне значення в межах `medium`–`high`.
- Поясніть метод дефазифікації (центроїд), і як зміна форм функцій (вужчі/ширші трикутники) змінить остаточну рекомендацію.

## Детальний розбір коду — `part3_smart_ac.py`

Мета: керування швидкістю вентилятора `fan_speed` у відсотках за двома входами: `temperature` (15..40 °C) та `humidity` (20..100 %).

1) Оголошення та сітки: `temperature` (15..40), `humidity` (20..100), `fan_speed` (0..100).

2) Функції належності (різні типи):
   - `temperature`: `trapmf` (холод), `gaussmf` (mild), `trapmf` (гаряче).
   - `humidity`: `trapmf` (dry), `gaussmf` (comfy), `trimf` (humid).
   - `fan_speed`: `trimf` для `low`/`medium`, `trapmf` для `high`.

3) Правила (мінімум 4, у коді 5):
   - Якщо висока температура або висока вологість → швидкість висока.
   - Якщо температура mild і вологість comfy → medium.
   - Якщо холодно і сухо → low.
   - Інші комбіновані правила для покриття сценаріїв.

4) Приклад сценарію:
   - `temperature=29`, `humidity=70` → симуляція дає `fan_speed` приблизно у вищому діапазоні (вивід виводиться на екран під час запуску).

5) Графіки (всі збережені в `results_part3`):
   - `part3_temperature_mf.png`, `part3_humidity_mf.png`, `part3_fan_mf.png` — функції належності.
   - `part3_fan_result.png` — візуалізація дефазифікації для поточного сценарію.

Як пояснювати результат:
- Опишіть, чому саме такі типи MF обрано (наприклад, trapmf для категорій із «плоскою» областю повного належання — холод/гаряче; gaussmf для плавних переходів у «комфортній» області).
- Поясніть дію конкретних правил: правило 1 (hot | humid → high) — забезпечує безпеку/комфорт при екстремальних умовах.

## Підготовка до захисту — можливі питання і короткі відповіді

1) П: Який метод дефазифікації ви використовували?
   - В: Бібліотека `skfuzzy` за замовчуванням використовує метод centroid (центроїд). Це означає, що ми обчислюємо центр маси агрегованого нечіткого множення, щоб отримати чітке значення.

2) П: Чому ви обрали саме такі форми membership functions (MF)?
   - В: Використався набори функцій, які логічно моделюють поведінку (trapmf — для крайніх «певних» ділянок, gaussmf — для плавних комфортних зон, trimf — прості трикутні наближення). Поясніть на прикладі температури: «cold» й «hot» мають плоскі області повного належання, а «mild» — більш округле/плавне.

3) П: Як вплинуть зміни параметрів MF на результати?
   - В: Вужчі MF зроблять систему більш «чутливою» (різкі переходи), ширші — більш «м’якою». Змініть sigma у `gaussmf` або вершини у `trimf`/`trapmf`, щоб продемонструвати ефект.

4) П: Які обмеження вашої системи?
   - В: Правила задані вручну — вони суб’єктивні. Хороша ідея — валідувати правила з даними або отримати експертні оцінки. Також відсутня нормалізація/врахування взаємодії на більш складному рівні (використовується базова логіка AND/OR).

5) П: Як могли б ви поліпшити систему?
   - В: додати ваги до правил, використовувати оптимізацію параметрів MF (наприклад, генетичний алгоритм), проводити крос-валідацію зі справжніми мітками (якщо доступні), додати більше даних та емпіричну перевірку.
