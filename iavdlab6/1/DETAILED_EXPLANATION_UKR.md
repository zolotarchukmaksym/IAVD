## Докладний розбір коду

Нижче — пояснення по файлах. Для кожного файлу вказано: призначення, ключові класи/методи, важливі фрагменти коду та інтерпретація.

### 1) `simple_model.py`

Призначення
- Реалізація простої моделі, де агенти рухаються випадково по сітці.
- Демонстрація `Mesa` (MultiGrid, Agent, Model) і `DataCollector`.

Ключові компоненти
- SimpleAgent(Agent)
  - `__init__(self, model)` — ініціалізація агента; викликається `super().__init__(model)` для реєстрації в моделі.
  - `step(self)` — отримує сусідні клітинки через `self.model.grid.get_neighborhood(self.pos, moore=True, include_center=False)` і переміщується в випадкову з них: `self.model.grid.move_agent(self, new_position)`.

- SimpleModel(Model)
  - `__init__(self, N, width, height)` — створює `MultiGrid(width, height, torus=True)`, додає N агентів з випадковими початковими позиціями, налаштовує `DataCollector` з агент-репортером `Position`.
  - `step(self)` — збирає дані `self.datacollector.collect(self)` і викликає `self.agents.do("step")` (mesa 3.x API) для виконання кроків усіх агентів.

Пояснення візуалізацій у кінці файлу
- Скрипт збирає дані з `DataCollector` через `get_agent_vars_dataframe()` — результат має індекси `AgentID` і `Step`.
- Для побудови траєкторії береться перший агент з набору: `agent_ids = data.index.get_level_values('AgentID').unique()` та `positions = data.xs(first_agent_id, level='AgentID')['Position']`.
- `x`, `y` — списки координат по кроках; потім будують `plt.plot` і `plt.scatter`. Додається colorbar, який показує час (номер кроку) за допомогою `cmap='viridis'`.
- Другий графік — фінальні позиції всіх агентів: береться останній `Step` й індексуються позиції всіх агентів.

Практичні зауваження / підказки для захисту
- `MultiGrid` дозволяє мати багато агентів в одній клітинці — це корисно для моделей взаємодії.
- `DataCollector` зберігає дані на кожному кроці, але пам'ятайте про пам'ять при великій кількості кроків/агентів.
- Поясніть, чому використовували `moore=True` (включає діагоналі) і `include_center=False` (щоб не залишатись на місці як варіант).


### 2) `boltzmann_model.py` (базова модель)

Призначення
- Імітує передачу грошей між агентами при контакті — класичний Boltzmann wealth model.

Ключові компоненти
- MoneyAgent(Agent)
  - `self.wealth = 1` — початкове багатство.
  - `move(self)` — рух як у простій моделі (випадковий крок по сітці).
  - `give_money(self)` — логіка передачі грошей. У коді є непотрібна перевірка `if other.wealth > 0: pass` — але основне правило застосовується після: якщо `self.wealth > 0` тоді випадковому іншому agent додається 1, у донора віднімається 1.
    - Зауваження: у цьому файлі є невелика недоробка (рядок із `if other.wealth > 0: pass`) — це не впливає на основну логіку, але його можна прибрати. Головна умова — `if self.wealth > 0: give 1`.
  - `step(self)` — викликає `move()` і `give_money()` (якщо має гроші).

- BoltzmannWealthModel(Model)
  - Ініціалізує N агентів (початковий капітал 1 у кожного), розміщує їх на сітці, робить `DataCollector` з `model_reporters={'Gini': compute_gini}` і `agent_reporters={'Wealth': 'wealth'}`.
  - `step` збирає дані та викликає `self.agents.shuffle_do('step')` — змішує порядок виконання, щоб уникнути систематичних ефектів.

Функція `compute_gini(model)`
- Розрахунок коефіцієнта Джині: алгоритм сортування багатств та обчислення за формулою (реалізація в коді повертає число в діапазоні від 0 до 1).

Візуалізація
- Гістограма розподілу багатства: `plt.hist(agent_wealth, bins=range(max(agent_wealth)+1))` — ось осі: по X — багатство (цілі одиниці), по Y — число агентів.
- Графік Gini в часі: `model.datacollector.get_model_vars_dataframe()` — відображає еволюцію нерівності.

Інтерпретація
- Класично для цієї моделі з дуже простим правилом очікуємо експоненційний розподіл багатства: велика частка агентів має мало грошей, невелика — багато.


### 3) `boltzmann_model_modified.py` (модифікація — заощадження)

Призначення
- Модифікація базової моделі: агенти зберігають мінімальний запас (параметр `savings_threshold`) — віддають гроші тільки якщо їх багатство більше цього порогу.

Ключові моменти
- ModifiedMoneyAgent(Agent)
  - `self.wealth = 5` — у модифікованій версії агенти починають із більшого капіталу, щоб обмін був осмисленим при непорожньому порозі.
  - `self.savings_threshold` — якщо `self.wealth > self.savings_threshold`, то агент дає 1 одиницю.

- ModifiedBoltzmannModel(Model)
  - Параметр `savings_threshold` передається всім агентам при створенні.
  - Далі збираються `DataCollector`-дані, запускаються симуляції для двох сценаріїв (поріг 0 і поріг 2) і порівнюються гістограми та криві Gini.

Інтерпретація результатів
- Якщо агенти не віддають останні 1-2 одиниці (мають мінімум, який не віддається), то кількість агентів з нульовим балансом знижується. Це робить розподіл більш сконцентрованим навколо невеликого інтервалу, знижуючи нерівність (Gini зменшується).

Зауваження по реалізації
- У модифікації початкове багатство встановлено в 5 — це зроблено, щоб поріг 2 мав зміст (якщо починати з 1, агенти ніколи не віддаватимуть, якщо поріг >= 1).

## Формула коефіцієнта Джині (що ви вказали в коді)

У файлі функція `compute_gini(model)` реалізована наступним чином (псевдокод):

1. Береться список багатств агентів: x = sorted(agent_wealths)
2. N = кількість агентів
3. B = sum(xi * (N - i) for i, xi in enumerate(x)) / (N * sum(x))
4. Gini = 1 + (1/N) - 2 * B

Коротко: коефіцієнт Джині обчислюється через відношення площ під кривими лоренца; код — обчислює його дискретно для масиву багатств.

Інтерпретація
- Gini = 0 → повна рівність (усі однаково багаті)
- Gini = 1 → максимальна нерівність (один має все)

Пояснення кроків у формулі
- Сортування гарантує, що вклад у нерівність обчислюється від найбідніших до найбагатших.
- B — допоміжна величина, що зводить суми у формулу нормалізовано.

Зауваження: при всіх агентських багатствах = 0 (сума = 0) треба берегти від ділення на нуль — у реалізації код не обробляє цей крайній випадок; у практиці перед обчисленням Gini потрібно перевірити sum(x) > 0 і в іншому випадку повертати 0 або None.

## Можливі питання від викладача і короткі відповіді (підготовка)

Q: Чому ви використовуєте `MultiGrid` замість `SingleGrid`?
A: `MultiGrid` дозволяє декільком агентам знаходитися в тій самій клітинці — це важливо для моделі обміну грошима, бо взаємодія відбувається при спільному перебуванні у клітинці.

Q: Як зміниться результат, якщо у агентів буде початкове багатство, відмінне від 1?
A: Це вплине на час досягнення стійкого розподілу і на початкові умови. Для модифікованої моделі початкове багатство було збільшено до 5, щоб поріг мав сенс; в іншому випадку при малому початковому багатстві агенти не зможуть віддавати.

Q: Чи враховується в моделі випадкова зміна кількості агентів?
A: Ні, модель фіксує кількість агентів. Модифікацію з народженням/смертю агентів можна додати як подальший розвиток.

Q: Чи коректно обчислюється Gini, якщо сума багатств = 0?
A: У поточній реалізації це не оброблено і може привести до ділення на нуль; варто додати перевірку `if sum(x) == 0: return 0`.

Q: Чому ви використовували `shuffle_do`/`do` замість класичного scheduler?
A: У Mesa 3.x API використовується `AgentSet` із методами `do` і `shuffle_do`. Це спрощує управління запуском кроків агентів і дозволяє легко міняти порядок виконання (shuffle) для усунення порядкових ефектів.


## Невеликі покращення та тестування (пропозиції)

1. Захист від ділення на нуль у `compute_gini`: якщо сумарного багатства немає, повернути 0.
2. Виправити дрібний артефакт у `boltzmann_model.py` (рядок `if other.wealth > 0: pass`) — його логічно видалити.
3. Додати збереження CSV-даних з `DataCollector` для подальшого аналізу: `model.datacollector.get_agent_vars_dataframe().to_csv('agent_positions.csv')`.
4. Простий unit-test: перевірити, що сумарне багатство після кожного кроку не змінюється (якщо модель не створює/не знищує гроші). Це можна зробити в окремому тесті `pytest`.

Приклад простого тесту (concept):
```python
# test_wealth_conservation.py (псевдо)
model = BoltzmannWealthModel(10, 5, 5)
initial_sum = sum(a.wealth for a in model.agents)
for _ in range(10):
    model.step()
assert sum(a.wealth for a in model.agents) == initial_sum
```

5. Додавати більше реплікацій (run multiple seeds) і брати усереднений Gini, щоб показники були статистично значимі.
